# Verification strategy and test evidence

Unit: money arithmetic, dates/Dhaka boundaries, validation, RBAC, status transitions, password verifier. Integration: in-memory/temp DB migrations, FK, immutable snapshots, transactional audit, concurrent numbering/stock, backup integrity and restore, attachment safety. UI: keyboard, forms, all routes and states, no dead controls, per-role navigation; E2E from activation to reinstall on actual Windows. Security: hostile IPC calls, unauthorized reports/export/direct entity IDs, XSS/CSP, path traversal, malicious files, session invalidation, wrong auth attempts, backup tampering. Print: actual generated PDFs at A4/A5/58/80/custom; extract Bengali and ৳, raster inspect and Windows physical output. Performance: seed at least 100k patients, 500k visits, 300k appointments, 200k invoices/payments, 500k stock movements and 100k attachment metadata; benchmark pagination/search/report/long profile and startup/memory against explicit baseline. No test seed in production.

Release evidence log per run: commit SHA, Windows version, architecture, DPI, printer model/driver, data sizes, command, result, artifact SHA256, screenshots/PDF output and failures. CI: lint/type/unit/integration/build/security audit/license inventory, Windows packaging, installer smoke. Manual: clean VM without dev dependencies, disconnected network, activation, wizard, E2E matrix in implementation plan, printing, uninstall with data retained and reinstall. Unobserved steps remain blocked; no CI success substitutes for a physical printer or clean-machine test. Every fix followed by focused retest plus full regression.
