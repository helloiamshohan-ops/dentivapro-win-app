# Print/PDF architecture

Immutable document DTO assembled in main process after permission check, with snapshot strings/prices and clinic identity at issue time. Print renderer is a separate local, sandboxed BrowserWindow with strict CSP, no IPC mutation and only sanitized content. Print preview is the same document HTML/CSS as final output. Electron `webContents.print` opens system printer dialogue (`silent:false`); PDF via `printToPDF` with selected size/margins and validated destination. Preview shows page count (calculated from rendered PDF), physical paper size, margins/orientation/scaling/profile; no silent printer selection. Profiles: A4 210×297, A5 148×210, 80mm and 58mm receipt, custom dimensions; printable area excludes margins and driver minimum. CSS `@page` dimensions and print media rules; receipt single-column. Dynamic text wraps, repeat table headers, prevent medicine-row splits where possible, pagination test with many rows. Bengali-capable bundled OFL fonts embedded in HTML/PDF, check glyph rendering by extracting text and raster inspection. Prescription two columns on A4/A5, single column on narrow paper; named dentist credentials snapshot, consultation hours, generous manual signature clearance. Invoice has **no dentist signature**. Test output by PDF text extraction + image comparison + actual print on Windows for all sizes; no claim about Bluetooth/wireless unless exposed by Windows driver.
