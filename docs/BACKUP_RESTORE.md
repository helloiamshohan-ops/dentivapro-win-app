# Backup and restore safety design

Manual destination folder and automatic 7/15/30-day option; due on next launch if app closed. Name `DentivaPro_Backup_YYYY-MM-DD_HH-mm-ss_schema-N.dpbackup`. Backup includes SQLite online consistent snapshot, attachments, config and schema/version manifest. Stage outside destination; verify SQLite integrity, attachment hashes, manifest hash; encrypt archive with operator passphrase using vetted authenticated encryption (Argon2id key derivation, AES-256-GCM per file with unique nonce); securely move only after complete verification. Never log passphrase. Backup to removable media recommended. Missing/low-space destination returns actionable error, not success. Retention is explicit; do not silently delete external backups.

Restore: owner reauthentication, confirm warnings; select **one** snapshot; validate signature/manifest/hash/schema and capacity before touching live files; MANDATORY pre-restore backup to an independent safe path, verify it, then close DB, stage and verify restored data, atomic directory swap on same volume, reopen DB and post-check, rollback on failure. Existing user data is retained as recovery copy until explicit cleanup. Incompatible newer schema blocked. No combining backups: conflicting identities and timelines cannot be safely merged. Test corrupt/truncated/old/new version, interrupted and disk-full restore, missing files, multiple candidate backups, unicode and attachments. The backup implementation is not complete merely because a file is copied.
